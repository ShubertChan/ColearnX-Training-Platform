# 安全设计与剩余风险

浏览器和第三方回调是两个独立的信任边界。浏览器不能声明自己拥有什么内容或该付多少积分；支付平台签名也不能替代本地订单核对。下面列出 W10 对这些边界的证据，方便维护者在变更时选择需要重跑的测试。

| 边界 | 服务器如何作决定 | 对照代码 |
|---|---|---|
| 登录与会话 | 密码/二次验证完成后才签发与会话绑定的访问令牌。API 同时检查签名、账号状态和服务端会话；撤销不等待 JWT 自然过期。刷新 Cookie 是不透明随机值，库内保存摘要。 | `apps/api/src/auth/auth.ts`、`apps/api/src/auth/mfa/` |
| 浏览器跨源写入 | refresh/logout 使用 Cookie 时校验与该 Cookie 绑定的 HMAC；显式 Origin 只接受配置的前端来源。前端、API 均启用 HTTPS。 | `apps/api/src/app.ts`、`apps/api/src/auth/auth.ts` |
| 数据访问与内容 | 订单查询按当前买家限定；没有授权和没有访问对象对外返回相同错误。上传检查真实内容并把未通过的文件隔离；签发的下载 URL 在有效期内仍是持有者凭据。 | `apps/api/src/orders/commerce.ts`、`apps/api/src/storage/` |
| 积分与支付 | 从数据库锁定商品、取价和检查授权。订单、授权、借贷分录和幂等回执同事务提交；Stripe 回调先校验原始请求签名，再核对本地交易、金额、币种及账号。 | `apps/api/src/points/ledger.ts`、`apps/api/src/payments/stripe.ts`、`apps/api/src/lib/idempotency.ts` |
| 审计 | 安全事件经独立连接落库，IP/UA 使用按用途区分的 HMAC。管理员读取安全事件需要角色、MFA 和绑定当前会话的近期 step-up。金融风控作业写告警，不自动拒付。 | `apps/api/src/security/events.ts`、`apps/api/src/admin/security-dashboard.ts` |

## 两项既有接受风险的复评

| 项目 | 本次证据与残余风险 | 建议及复核触发条件 |
|---|---|---|
| F-13：生产/预发刷新 Cookie 使用 SameSite=None | 已验证 staging 配置生成 Secure、HttpOnly、限定认证路径的 Cookie。跨站请求仍可能携带 Cookie；错误令牌和非允许来源遭拒。无 Origin 的合法客户端依赖令牌校验。预发的前端和 API 是同一站点的不同源，不能单凭“跨源”断言一定需要 None。 | 保留本次兼容行为，建议发布负责人用支持的浏览器验证 Lax 下的登录、刷新和退出；如果没有真正跨站的部署需求，再收紧。前端或 API 域名、Cookie Domain、嵌入登录方式发生变化时复核。 |
| F-19：注册可枚举 | 旧登记册的 202 描述不能覆盖当前实现。邮件传输用内存替身时，新邮箱返回 202；已验证邮箱冲突返回 409 `EMAIL_ALREADY_REGISTERED`。因此攻击者能区分，限流只能降低探测速率。既有待验证账号的续办还要求原密码。 | 建议产品与安全负责人重新决定是否保留该交互。若要消除差异，需要统一状态、正文及可观察的续办 Cookie 行为，再测试重复注册不能接管账号。注册/验证页改版或出现批量探测时重新评估。 |

以上是复评结论，没有代替团队续签风险接受。W2 ASVS 基线保留在[原评估](W2-asvs-gap.md)；本次攻击样本不足以推算新的全量 L2 满足率，也不能据此宣称达到 80%。

## 值班人员如何处理访问签名密钥泄露

先记录事件时间、受影响的签名用途、运行实例和已发布版本；证据只留请求标识、计数和日志位置。冻结发布，隔离或停止旧节点签发登录、刷新和二次确认请求，以免吊销与新签发互相竞速。通过密钥管理渠道生成新的访问签名密钥，在全部替代节点配置相同的新版本，不把值带入工单、CI 日志或命令历史。

在所有签发入口暂时停止后，用已有的受控数据库维护通道吊销全部未吊销会话，核对数量并确认没有遗漏。用户界面的“退出其他设备”会保留当前会话，不适合这次事件。切换并摘除所有接受旧签名的节点，然后验证旧访问与刷新凭据均失败、新登录和刷新均成功。若验证失败，保持入口受限并修复新配置，不恢复泄露的密钥。恢复流量后复核会话异常、登录失败和用户重新登录情况，记录真实恢复时间与遗留项。

本演练只轮换访问令牌签名密钥。`MFA_SECRET_KEY` 加密已绑定的 TOTP 种子，不能照此直接替换；其泄露或丢失需要单独的重加密或重新绑定方案。测试中的全量吊销仅存在于受空库、回环地址和受限角色检查约束的演练脚本，没有增加线上“吊销所有人”的 API。
