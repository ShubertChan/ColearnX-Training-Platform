## 2. 信任边界与数据流

```
                    ┌─────────────── TB1 ───────────────┐
   [浏览器 SPA] ────┤  公网 HTTPS / CORS 白名单 / CSRF   ├──→ [Express API]
    Vite/React      └───────────────────────────────────┘      apps/api/src/app.ts
        │                                                            │
        │                                                            ├── TB2 ──→ [PostgreSQL]
        │                                                            │           4 个隔离角色
        │                                                            │
        │                                                            ├── TB4 ──→ [Cloudflare R2]
        │                                                            │
        │                                                            ├── TB5 ──→ [Resend 邮件]
        │                                                            │
        └────────────────── TB6 ─────────────────────────────────────┘
           预签名 URL 直传/直下（**不经过 API**，API 无法逐字节检查）

   [Stripe] ──── TB3（入站 webhook，公网可直达，无需认证头）────→ /api/v1/payments/stripe/webhook
```

**必须单独关注的两条边界：**

- **TB3** 是唯一一个"外部系统主动打进来"的入口，且它刻意绕过了 `express.json()`
  （`app.ts:44` 注释说明原因：Stripe 验签需要原始字节）。任何对该路由的中间件调整都可能静默破坏验签。
- **TB6** 是唯一一条"用户数据不经过 API"的路径。API 只能在上传完成后通过
  `HEAD` 事后核对（`content-assets.ts:251`），**无法阻止用户上传任意字节**。

### 已接受风险的书面理由

- **F-13**：前后端分离部署跨源，`sameSite=lax` 会使 refresh cookie 完全失效。补偿控制为
  「CSRF token 常数时间比对 + Origin 严格白名单 + refresh token 轮换与重放检测」三重，
  攻击者需同时拿到 CSRF token（不在 cookie 中，无法被跨站读取）才能成功。复评时点：W10。
- **F-19**：注册接口对已存在的邮箱返回 202 而非 409（`auth.ts:248` 的设计意图），
  该枚举面已由产品形态决定。收敛它需要重构整个注册续期流程，成本高于收益。复评时点：W10。

## 5. 引入新控制时必须评估的反向风险

这一节是 W3 实现之前的强制前置，避免"加安全反而开新洞"：

1. **账号锁定 → 拒绝服务**：攻击者可用他人邮箱故意失败登录，把受害者锁在门外。
   - 缓解：锁定必须是**渐进式且自动解除**的，不能是需人工解锁的永久锁；
     锁定状态**不得**通过响应区分（否则同时成了枚举 oracle）；密码重置成功必须清除锁定，
     给受害者留一条自助恢复通道。
2. **密码重置 → 账号接管**：重置流程本身是最常见的接管入口。
   - 缓解：令牌单次使用、短 TTL、重置后吊销全部会话、**不自动登录**、
     响应对不存在的邮箱与存在的邮箱完全一致。
3. **泄露口令检查 → 口令外泄给第三方**：绝不能把口令或完整哈希发给外部 API。
   - 缓解：仅使用 k-匿名（只发 SHA-1 前 5 位）+ `Add-Padding` 响应填充。
4. **安全事件表 → 二次泄露面**：安全日志会聚集 PII。
   - 缓解：只存 HMAC 后的 IP/UA，`context` 字段禁止写入原始凭据，设置保留期。
