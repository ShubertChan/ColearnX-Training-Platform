## 3. 2026-08-30 首次全栈 MVP：eb1cfbd

这笔提交与合并提交 1354950 一起单独计为一个功能阶段。它是新增 colearnx-v1.0 项目，并未重写根目录原有 index.html/enhancements.js。新增 81 个文件的精确清单在附录中。

### 3.1 React 前端与 API 接入

- 建立 React/Vite 应用、React Router 路由、Layout、通用 UI、样式、图片和依赖/构建脚本；页面覆盖认证、账号、Marketplace、Creator/Trainer、Learning、Wallet 与 Admin。
- 建立 src/api 下的 auth、admin、catalog、commerce、governance、payments、refunds、wallet 客户端与统一 client，使用 Bearer access token 及携带凭据的请求；开发代理将 /api 转发到 API 服务。
- PlatformContext 接入身份、角色、个人资料、余额与流水、商品、订单、退款、角色申请、创作者提交及管理员队列。购物车保留为结算前内存选择，真实价格、订单与授权由服务端确定。
- 支付页面提交服务端套餐 ID，跳转 Stripe Checkout 后轮询充值状态；退款与购买展示接入 API。同时保留既有页面、示例数据与 courseState 辅助函数，不能仅因目录存在就认定每个原型交互都已接入生产服务。

### 3.2 Express/TypeScript API

- 建立 apps/api，包含 app.ts/server.ts、环境校验、统一成功/错误封装、请求 ID、日志、CORS、安全中间件及请求限流。
- 身份模块提供注册、登录、刷新、退出、读取/修改个人资料、角色鉴权；密码使用 Argon2，access token 使用 JWT，refresh session 以哈希记录。
- catalog 提供公开商品查询、Creator 内容草稿与提交、Trainer 课程创建与提交、管理员发布审核；governance 提供角色申请与讲师认证。
- orders/commerce 提供积分购买、订单与明细、购买时快照、课程报名与内容授权；并发关键路径使用数据库事务和行锁，价值变更使用幂等记录。
- wallet、points/ledger 与 payments/stripe 提供账户余额、不可变积分账本、充值套餐、测试支付、签名 webhook、重复事件处理；充值金额/点数从服务端套餐取得。
- refunds 提供资格判断与审核：Local 在 V1 不退款；Live 需至少提前 72 小时；Cloud/Record 需购买后 72 小时内且记录进度不超过 10%。这些是当时代码规则，不是本报告新增的政策。
- admin 提供账号列表/详情、停用/恢复、角色授予/撤销与访问删除，以及充值套餐、积分调整、收入分配策略、Live 课程完成/取消操作；保留管理员操作审计。

### 3.3 数据库、运行方式与交接
